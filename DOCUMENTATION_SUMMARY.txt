YOUR ISSUE EXPLAINED
================================================================================

ERROR MESSAGE:
  "Invalid file: Git-2.54.0-64-bit.exe: File must be a valid UTF-8 text file
   or a supported binary (images, audio, video, PDF, Word/Excel/PowerPoint)"

ROOT CAUSE:
  Binary executable file (.exe) rejected by file validator that only accepts
  UTF-8 text or specific media formats.

SOLUTIONS (3 OPTIONS):
  1. Add 'application/octet-stream' MIME type to allowed files
  2. Create separate '/api/updates/upload-binary' endpoint
  3. Use correct Content-Type header: 'application/octet-stream'

SYSTEM OVERVIEW
================================================================================

What it does:
  • Checks for updates every 60 minutes
  • Downloads update .exe to cache
  • Verifies SHA256 checksum
  • Installs silently (if configured)
  • Restarts app with new version

Architecture:
  IUpdateService (interface)
  └─ AbstractUpdateService (base logic)
     └─ Win32UpdateService (Windows impl)

Update Flow:
  1. Check update server
  2. Compare versions
  3. Download .exe if new version exists
  4. Verify checksum
  5. Run Inno Setup installer
  6. Restart app
  7. Done ✅

State Machine:
  Uninitialized
  └─ Idle (ready to check)
     ├─ CheckingForUpdates
     ├─ AvailableForDownload
     ├─ Downloading
     ├─ Downloaded
     ├─ Updating
     └─ Ready (restart)

Key Interfaces:
  • IUpdateService - Main contract
  • IUpdate - Update data from server
  • ISyncfusionUpdate - Extended for Syncfusion
  • State - Current update status
  • Configuration - update.mode, enableBackgroundUpdates

YOUR 3-STEP FIX
================================================================================

Step 1: Identify the validation layer
  └─ Find where file type checking happens in your upload endpoint

Step 2: Choose a solution (pick one):
  
  Option A: Add MIME types
    └─ Add to allowed types: 'application/octet-stream',
                             'application/x-msdownload',
                             'application/x-executable'
  
  Option B: Create binary endpoint
    └─ POST /api/updates/upload-binary
       └─ Skip text-only validation
  
  Option C: Fix Content-Type header
    └─ Use 'application/octet-stream' instead of 'application/json'

Step 3: Test
  └─ Upload a .exe file
  └─ Verify it succeeds
  └─ Confirm update system can access it

================================================================================
CONFIGURATION QUICK REFERENCE
================================================================================

update.mode:
  • "default"  → Auto-check every 60 min, download, auto-install
  • "manual"   → User must click "Check for Updates"
  • "start"    → Only check at app startup
  • "none"     → Updates disabled

update.enableWindowsBackgroundUpdates:
  • true  → Auto-install silently (no restart prompt)
  • false → Download only, user must restart
